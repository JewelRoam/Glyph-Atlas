# 字脉 · Glyph Atlas

**人类书写体系演化可视化**

把世界书写体系的传播与亲缘画成一张可缩放的图；从任一体系进入其节点页，查看档案、直接来源与去向，以及整表字形的一一变化。

## 立意

字脉把人类不同书写体系放回同一条时间轴，追踪它们如何诞生、借用、分叉、传播、被替代，直到某一天不再有人书写。它关心存活下来的文字，也关心哪些分支停止了、在哪个年代停止、哪些字形只剩下残片，以及一套文字消失时，依附其上的文献、技艺、信仰和知识如何一起变得无法阅读。

这种消失常常没有清晰的时刻。一所学校不再教某种文字，一批孩子改用另一套字母，一本经卷被收进仓库，最后一位能读碑文的人去世。很多年后，人们还能看见墙上的刻痕、纸上的墨迹，却不知道它们写下了什么。

**一种书写传统可能需要数百年甚至数千年才形成，它的消失可能只需要一场焚毁、一次文字改革、一代人停止传授。** 在数字时代，边缘化还沿着字体、编码、语料和输入法扩散。使用一套文字的人越少，工具越少；工具越少，下一代越难进入这套文字。数字工具和 AI 正在把这种差距继续拉大，让大多数文字在同一种技术尺度下显得“不可用”。

字脉是一项保存工作，呈现给公众的叙事围绕失去展开。断裂、空白、残卷和无人能读的文献占据前景。复兴会留在记录里，故事仍然从失去写起。

## 产品

字脉把书写体系放回时间与谱系中：全图展示谁来自谁、谁影响了谁；进入任一体系后，可以查看档案、直接来源与去向，并在中央字形场阅读完整字母表、代表字或实物图版。

全站只有两种空间：

1. **演化全图**：全部书写体系的有向图，横轴是线性年代，纵轴按谱系分泳道。
2. **体系节点**：从一个节点进入，阅读体系资料，并通过左右两侧的完整关系切换前后体系。

「查找文字」是全图上的覆盖层。点击全图节点或检索结果都会直接进入体系节点。

## 界面

### 演化全图

- 时间横轴从公元前 3300 年到 2030 年，按真实年份等比例展开。
- 12 个谱系分泳道排列，节点按年代落位，连线区分直系演变、借用、影响与造字模型。
- 悬停节点会突出其祖先与后代；点击直接进入体系节点。
- 缩放、平移、总览与标注开关均在画布右上角。
- 首次进入会按当前画布尺寸居中适配；从体系节点返回时恢复离开前的视域。
- 标签在空间不足时主动折叠，页面右下角只报告实际折叠数量。

### 体系节点

体系节点是每种文字的唯一入口，集中展示：

- 名称、类型、起源、年代、发源地、使用国家或地区与书写方向。
- 左侧完整列出直接来源，右侧完整列出直接去向，并按直系演变、借用、造字模型与影响分组。
- 中央字形场按材料类型呈现完整字母表、语素文字代表字或授权图版；三者共用同一位置。
- 点击任一侧的关系会切换整个节点，不保留节点内的嵌套切换器。
- 切换时保持当前页面滚动位置；来源、去向与字形场一起更新。
- 只有直接 `descent` / `borrowing` 关系且两端有手工核对的共享槽位时，字母才逐字形变。
- 其它关系使用整场交叉淡变；一边独有的字母飞入或飞出，自动补位不构成形变证据。
- 没有可靠字体或授权素材时不渲染字形场，不以现代书体顶替。

节点页使用 `?script=<scriptId>` 定位。浏览器前进与后退可以恢复对应体系；返回全图时恢复离开前的视域。

### 查找文字

「查找文字」覆盖全图，可按名称、英文名、国家、地区、谱系与状态筛选，并按年代或名称排序。快捷键为 `⌘ K` / `Ctrl K`，`Esc` 关闭。

## 数据模型

### 节点

`WritingSystem` 是图谱节点，记录名称、类型、起源、年代、国家或地区、Unicode 区块、代表字形、字体与来源引用。

类型覆盖语素文字、语素音节文字、音节文字、辅音音素文字、元音附标文字、全音素文字、特征文字、速记、混合系统与未破译文字。

### 关系

`GraphRelation` 是一条有向边，必须带语义与证据状态：

- `descent`：直系演变。
- `borrowing`：借用字母、字形或整套书写制度。
- `influence`：可核实的设计或观念联系，不声称直系血缘。
- `model`：参照另一体系创制，字形本身不必同源。

`evidence: sourced` 表示这条边已有来源；`pending` 表示关系分类已登记、逐边证据仍待补。当前 49 条边为 `sourced`，115 条为 `pending`。界面中的线型与审计报告读取的是同一份边表。

### 内部材料轨道

`Lineage` 是一组按时间排列、具有可比较字形的材料阶段。每个阶段必须指向真实书写体系，并尽量提供字符、SVG 路径或图片之一以及来源。

材料轨道用于整理字形素材、检查覆盖与审计来源，产品入口固定在体系节点。节点之间的可见关系由 `graphRelations` 定义；同一字母的跨文字对照与直接传承分别记录。

### 文件与数据流

- `glyphSets` 提供每个体系的字形表。
- `letterSlots` 提供跨文字同源槽位，让新增、合并与缺失字母可以在整表动画中对位。
- `glyphPaths` 提供可插值的逐字轮廓。
- `glyphSources` 决定使用字体、图片还是有意留空。
- `scriptContext.ts` 把节点、素材、图谱关系与材料轨道组合成单一的只读上下文。

这样，图谱节点、检索卡片和体系节点读取的是同一套数据，不维护第二份详情数据。

## 图形与形变

### 线性时间

`x = (year − 前3300) × 每年宽度`。时间域共 5330 年，公元前占约 62% 的横向空间。两段年代在屏幕上的横向距离始终与真实年数成比例，不按标签密度拉伸分段。

图谱采用确定性布局。泳道位置、年代坐标与标签避让都由布局计算得出；窗口尺寸变化只改变视域，年代比例保持不变。

### 矢量形变

`src/lib/morph.ts` 把两端 SVG 轮廓拆成子路径，按弧长采样，再按重心、面积、包围盒与绕向配对轮廓。闭环会寻找最短起点错位，多余子路径收缩成点或从点长开。

体系切换时，`GlyphField` 先检查关系语义与共享槽位：只有直接演变 / 借用且两端存在人工核对的同源位，才逐字母执行点对点形变。没有可靠对应时，整场内容交叉淡变。新增或消失的字母通过飞入、飞出和 FLIP 重排呈现，不用突然换图。

### 动效原则

- 字形变化服务于辨认，不制造无意义的持续运动。
- 体系切换、字母增删与图版替换各自只在状态变化时发生。
- 系统设置 `prefers-reduced-motion` 时关闭非必要动画。
- 所有主要操作保留键盘焦点与清晰的焦点样式。

## 字形来源政策

每格字形都必须回答“它从哪里来”。

1. **有合适的开源字体**：使用覆盖该字符的字族，并登记到 `tools/font-verdicts.tsv`。
2. **没有可靠字体但有可靠材料**：使用登记过作者、授权与出处的实物图或图版。
3. **两者都没有**：留空并说明原因，不用现代书体冒充历史字形，也不回退到系统字体。

字形来源台账按体系逐条核验。当前记录了 204 条馆藏记录，均有可靠的字体或图版来源，已知字形来源错误为 0。查找页优先显示逐字图，没有逐字图时使用该体系的第一幅图版。

实物图版显示在稳定的白底容器中，并保留可放大查看的原始比例。所有图版的作者、许可和原始链接记录在 [`public/glyphs/CREDITS.md`](public/glyphs/CREDITS.md)。

## 数据校验与质量底线

`npm run validate` 当前检查：

- `id` 唯一性与引用存在。
- 父系年代不晚于子系，允许约数造成的时间宽容。
- 起源性质、父系和图谱边自洽。
- 年代落在材料时间域内。
- 内部材料轨道至少两段、顺序递增、阶段引用有效。
- SVG 路径使用 `0–100` 的 `viewBox`。
- Unicode 区块名与样例码位一致。
- 字体确实覆盖声明字形，不静默回退。
- 每条图谱边语义有效，无重复、自环或环。
- 每个体系都有字体台账结论，已知 `wrong` 会让构建失败。
- 字表、同源槽位和字形来源可以相互解释。

视觉回归另以浏览器检查真实构建产物。验收底线是桌面 1280 / 1440 / 1920 下标签重叠为 0，所有检查视口横向溢出为 0，浏览器 console error 与 pageerror 为 0，手机端可进入体系节点并打开中央字形场。

## 如何新增书写体系

1. 在 `src/data/writingSystems.ts` 添加节点，补齐名称、类型、年代、国家或地区、代表字形、Unicode 区块与来源。
2. 在 `src/data/graphRelations.ts` 添加有向关系。写清楚 `kind` 与 `evidence`；不要把字体相似当作谱系证据。
3. 在 `src/data/glyphSets.ts`、`glyphPaths.ts` 或 `glyphSources.ts` 提供可靠字形；无法确认时留空并写原因。
4. 在 `tools/font-verdicts.tsv` 登记字体结论。使用新字族时先运行 `npm run validate`，再在字体审看台确认字面。
5. 如加入实物图版，把文件放入 `public/glyphs/<scriptId>/`，登记 `glyphPlates.ts` 与 `public/glyphs/CREDITS.md`。
6. 运行 `npm run check && npm run build`。涉及版式或交互时再运行 `npm run shots`。

### 如何补充内部材料轨道

1. 在 `src/data/lineages.ts` 添加按时间递增的材料阶段，至少两段。
2. 每段指向真实体系，并提供 `char`、`path` 或已登记素材。
3. 写明材料来源。阶段描述按语文学材料核对，不以视觉相似代替传承证据。
4. 如需整表动画，在 `letterSlots.ts` 补同源槽位；没有可靠对位的字会走自动补位，不参与几何轮廓形变。
5. 运行 `npm run validate` 与 `npm run audit:coverage`，检查新增节点是否能从图谱与检索正确进入。

## 已知边界

- 203 个图谱节点都能打开体系节点，且都有可铺开的字形素材；高迪文使用 11 世纪《八千颂般若经》写本图版，不排逐字字表。
- 164 条图谱边中，49 条已有逐边来源，115 条仍为 `pending`；关系本身与证据完整度在数据中明确区分。
- 40 条内部材料轨道共有 144 个阶段。其中一些阶段缺少可插值的 SVG 轮廓；没有可靠对应时只做整场淡变，不伪造形变。
- 利比亚—柏柏尔字母到提非纳文目前只核实到书体传统的阶段承接；古代字母与新提非纳字母的逐字对应尚未查清，相关节点不做整表形变。
- 汉字、埃及圣书体、玛雅文等语素文字不追求铺满全部字符；中央字形场只展示有来源的代表字或实物图版。
- 少数体系只有整幅图版，没有逐字字表；这类材料适合证明书体样貌，不适合统计字母覆盖率。
- 当前仍有部分字体子集较大，Vite 会报告超过 500 kB 的 chunk。检查与构建通过，加载策略仍可继续优化。
- 图形与文字数据会继续校正；发现错误时撤销不可靠关系或字形，保持数据来源可解释。
